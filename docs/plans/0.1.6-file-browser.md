# Plan: file browser (0.1.6)

Status: proposal. A sidebar listing the Markdown files of one chosen folder (the
workspace), opening them in tabs. Builds on the tabs work
([0.1.6-tabs.md](0.1.6-tabs.md)); file watching arrives in 0.1.7.

## Principles kept

- The Markdown file is the document. The browser only lists, opens, creates and
  renames files; every read and save still goes through the per-tab Rust
  baselines and conflict checks.
- Access stays explicit. Today Rust only touches files chosen in a native dialog
  or passed by the OS. A workspace widens that to *one folder the user chose*,
  and nothing outside it.
- Never lose work: renaming an open file updates its tab; nothing is deleted
  permanently.

## The workspace

- **File → Open Folder…** picks a folder with the native dialog; `textgate ~/notes`
  (a folder argument) does the same. One workspace per window; choosing another
  replaces it. **File → Close Folder** hides the browser.
- The folder is remembered and reopened at the next launch. Rust stores it in the
  app's config folder (beside the themes) and re-grants it at startup; if the
  folder is gone, the browser shows that instead of failing.
- Rust grants the folder as a *root*: a path is allowed if it is inside a root
  after resolving symlinks, so a link inside the workspace cannot reach outside
  it. Files picked individually keep working exactly as now.

## What the browser shows

- Folders, Markdown files (`.md`, `.markdown`) and text files (`.txt`), as in
  the Open dialog; other files are hidden.
  Folders starting with `.` (`.git`, `.obsidian`) and `node_modules` are hidden.
- Folders first, then files, each sorted naturally (`note 2` before `note 10`),
  case-insensitively.
- Folders load when expanded, so large trees stay fast; expanded folders are
  remembered with the workspace. A folder with thousands of entries shows the
  first 1,000 and says how many were left out.
- The file in the current tab is highlighted, and its folders expand to show it.
  Open files (in any tab) are marked; unsaved ones show the dot.
- Without file watching, the tree refreshes when the window regains focus, after
  Textgate's own changes, and on **Refresh**.

## Actions

| Action | How |
| --- | --- |
| Open | Click, or Enter; opens in a tab (or switches to it) |
| New file | Button / context menu on a folder; asks for a name, adds `.md` if none, opens it in a tab (created on first save, as from the command line) |
| New folder | Button / context menu |
| Rename / move | Context menu, or F2; an open file's tab and Rust baseline follow it. Moving by drag and drop can come later. |
| Delete | Moves to the system trash (the `trash` crate), after a confirmation; an open tab stays open, marked as deleted, so nothing is lost |
| Reveal | "Show in file manager" |

## Layout and keyboard

- The left sidebar gets two views, **Files** and **Outline**, switched by a small
  tab pair at its top (View → Files / Outline, with shortcuts). Both stay hidden
  with the existing Outline toggle, renamed **Sidebar**.
- A `role="tree"` with `treeitem`s: Up/Down move, Right/Left expand/collapse,
  Home/End, type-ahead by name, Enter opens, F2 renames, Delete trashes. Part of
  the F6 cycle (as the sidebar).
- The sidebar width becomes adjustable by dragging its edge, remembered per device.

## Rust

| Command | Does |
| --- | --- |
| `open_workspace(path)` | Validates a dialog-chosen folder, makes it the root, stores it |
| `workspace()` | The stored root, if it still exists (re-granted at startup) |
| `list_folder(path)` | Entries of one folder inside the root: name, kind, Markdown or not |
| `create_file`, `create_folder` | Inside the root; never overwrite (`create_new`) |
| `rename_entry(from, to)` | Inside the root; refuses to replace an existing entry; updates the Rust document holding the file |
| `trash_entry(path)` | Moves to the system trash |

All path checks resolve symlinks and require the result to stay inside the root.
Renaming an open document updates its slots in `Documents`, so saves keep the
right baseline.

## Steps

1. **Workspace roots in Rust** (done). Root grants (resolved, symlink-safe), storage
   and startup re-grant, `open_workspace`, `workspace`, `list_folder`, with tests
   for escapes through `..` and symlinks.
2. **Read-only browser** (done). Sidebar views, the tree with lazy folders, sorting,
   filtering, keyboard tree, opening into tabs, current-file highlight, refresh.
3. **Creating.** New file and new folder.
4. **Rename and trash.** With open tabs following renames.
5. **Folder argument and polish.** `textgate <folder>`, sidebar width, remembered
   expansion, docs and platform checks.

## Out of scope for 0.1.6

File watching (0.1.7), several workspaces at once, search across files, drag and
drop, showing non-Markdown files, links between notes (0.1.7).
