# Plan: tabs (0.1.6)

Status: proposal. Several documents in one window, one tab each. The file
browser (also 0.1.6) builds on this and is planned separately.

## Principles kept

- The Markdown file is the document. A tab never re-serializes its file; each
  tab keeps its own exact disk baseline, line-ending format and BOM.
- Every save still goes through the Rust conflict check for *that* tab.
- One editor, many states. A tab is a CodeMirror `EditorState`; switching tabs
  calls `view.setState`, so undo history, selection and folding stay per tab
  with no extra editor instances.

## Where the single-document assumption lives today

| Place | Today | With tabs |
| --- | --- | --- |
| `src/documents.rs` `Documents` | One `opening`, `baseline` and `approved` slot | Maps keyed by a document id; `close_document` drops a tab's entries |
| `web/main.js` globals | `path`, `savedDoc`, `savedFormat`, `dirty()` | Fields of the active tab |
| `replaceDocument` | Swaps in a new state, clearing undo | Opens a tab (or reuses an untouched Untitled one) |
| `document-opener.js` | Asks to discard before replacing | No discard needed; opening adds a tab |
| `external-open.js`, `launch.rs` | One file; "already open" compares raw paths | Several files per request; identity by resolved path |
| `vim-commands.js` | `:q` closes the window | `:q` closes the tab; the last tab closes the window |
| Quit / window close | One `canDiscard` | Lists every tab with unsaved changes |

## Design

### Rust

- Document ids are issued by Rust (`new_document() -> u32`) and passed to
  `open_document`, `keep_document`, `save_document` and `close_document`.
  Untitled tabs get an id too, so Save As works the same everywhere.
- Identity is the resolved target path (`resolve()`, already symlink-aware).
  `open_document` reports the id of a tab that already has that file, and the
  frontend switches to it instead of opening a second copy. Two tabs editing one
  file would make each other's baselines stale.
- Save As onto a file open in another tab: refuse with "That file is open in
  another tab" (close that tab first). Simple and safe for 0.1.6.
- `launch.rs`: accept several files (`textgate a.md b.md`, multi-select in
  Finder or a file manager). Each becomes a queued request in arrival order.

### Frontend

- New `web/tabs.js`, DOM-free and unit-tested: the tab list and active tab;
  add, activate, close, move, next/previous, find by path; names disambiguated
  by parent folder when two tabs share a file name (`notes.md — work`).
- A tab: `{ id, path, state, savedDoc, savedFormat, scrollTop }`.
- Switching saves the old tab's `view.state` and scroll position, then
  `setState`. Global settings (Live/Source, Vim, line numbers, spell check)
  are reapplied with compartment `reconfigure` when the incoming state differs,
  so they stay global, not per tab. Vim returns to Normal mode on switch.
- Header, window title, outline, statistics and preview follow the active tab.
  The existing caches are keyed by `Text` identity, so they invalidate correctly.
- Opening a file when the active tab is an untouched Untitled tab (including the
  welcome text) reuses it rather than leaving an empty tab behind.

### Tab bar

- Between the toolbar and the editor, `role="tablist"`; each tab `role="tab"`,
  `aria-selected`, roving tabindex with arrow keys, Home/End; the panel is the
  editor. Dirty marker as now: ● plus visually hidden "Unsaved changes".
- Close button per tab (skipped by Tab), middle-click closes, full path as tooltip.
  The bar scrolls horizontally when tabs overflow and keeps the active tab in view.
- F6 pane cycling gains the tab bar.

### Commands and shortcuts

| Action | Keys | Menu |
| --- | --- | --- |
| New tab | Ctrl/Cmd+N (now opens a tab) | File → New |
| Close tab | Ctrl/Cmd+W | File → Close Tab |
| Next / previous tab | Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+PageDown / PageUp (Cmd+Shift+] / [ on macOS) | View |
| Go to tab 1–9 | Ctrl/Cmd+1…9 (9 = last) | — |
| Vim | `gt` / `gT`, `:tabnext` / `:tabprevious`, `:q` closes a tab, `:qa` closes all (E37 if any are unsaved) | — |

### Closing with unsaved changes

- Closing one dirty tab: **Save / Don't Save / Cancel**. Save runs the usual save
  (conflict check included); the tab closes only if the save succeeded.
- Quit or window close with dirty tabs: one prompt listing them; "Discard all"
  or Cancel. Saving each first is left to the user (or Save All, if added).

## Out of scope for 0.1.6

Restoring tabs after a restart (fits with crash recovery in 0.1.7), dragging
tabs between windows, split views, pinned tabs.

## Steps

Each step lands with tests and leaves the app working.

1. **Rust per-document baselines** (done). Document ids, maps instead of single slots,
   `close_document`, identity lookup, Save As refusal. Frontend passes the id of
   its single document. No visible change.
2. **Tab model** (done). `web/tabs.js` plus tests; move `main.js` globals into the
   active tab, still with one tab.
3. **Tab bar and switching** (done). New/Open/close/switch, shortcuts, native menus,
   accessibility, scroll restore.
4. **Closing and quitting.** Dirty-tab prompts, quit listing, Vim tab commands.
5. **Opening from outside.** Several files from the command line and file
   manager; already-open files switch tabs instead of prompting.
6. **Docs and checks.** README, shortcuts dialog, release notes; desktop checks
   on Linux, macOS and Windows.

## Tests to add

- Rust: two documents keep separate baselines; a conflict in one does not affect
  the other; closing drops the baseline; opening the same file through a symlink
  finds the existing document; Save As onto an open file is refused; launch
  parsing of several files.
- JS: `tabs.js` operations and name disambiguation; in the app, undo stays per
  tab across switches, dirty markers are per tab, mode/Vim/line-number settings
  survive switching, closing a dirty tab prompts, a pristine Untitled tab is reused.
