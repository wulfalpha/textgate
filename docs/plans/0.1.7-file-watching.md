# 0.1.7: outside file changes

Watch open documents' parent directories and the workspace's visible folders.
Use native notifications as hints, with exact byte comparisons on notification,
window focus and a 30-second fallback. Parent-directory watches cover editors
that save through atomic replacement. Watches never grant file access.

- Clean tabs reload changed UTF-8 text without stealing focus. Preserve the
  primary selection (clamped to the new length), BOM and line-ending metadata.
  Reload starts a fresh undo history so Undo cannot silently resurrect an old
  disk version. Inactive tabs update in place.
- Dirty/recovered tabs keep their text and show a warning when active. Reload
  from disk requires explicit discard approval. Typing during a read cancels
  that reload; typing during approval requires fresh approval.
- Deleted or externally renamed files keep their text and become unsaved.
  Save asks before recreating the old path. External renames are not followed.
- Invalid UTF-8, unreadable files and notification failures show a warning.
  Failed reads do not advance the native save baseline. Save conflict checks
  remain authoritative, including changes that happen after a notification.
- Notifications refresh the file browser's root and expanded folders. Closed
  folders are read when opened. Only the first 512 supplied expanded folders
  get notifications; every expanded folder still gets fallback refreshes.
- Own saves do not trigger reloads because their exact baseline matches disk.
  No automatic writes, source-file autosave or spellcheck changes are included.

Verification covers same-size edits, deletion, scope restrictions, atomic
replacement, queued scans, typing during reads/commit and baseline failures.
Native package and manual UI checks must pass before merging.
