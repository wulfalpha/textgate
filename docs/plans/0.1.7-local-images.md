# 0.1.7: local images

Render relative local PNG, JPEG, GIF and WebP images using normal Markdown:

```markdown
![Description](images/photo.png)
```

For names containing spaces, use `![Description](<images/My photo.png>)` or
encode spaces as `%20`. Keep macOS screenshot filenames exactly as written,
including any narrow nonbreaking space before AM/PM. Bare spaces in an
unwrapped destination are Markdown syntax, not a filesystem lookup failure.

- Resolve relative to the saved note's folder, or the workspace root for an
  Untitled note. Open Folder grants access to images within that workspace;
  paths outside it need an existing native file grant. Ungranted symlink escapes are
  refused. Loading an image does not grant a new path or change a document.
- Native code reads regular files up to 8 MiB, checks supported file signatures
  and returns the bytes as image data. No broad asset protocol or additional
  filesystem permissions are enabled. Remote, absolute, network and embedded
  source URLs are blocked; SVG is deferred.
- Source Preview renders images, including reference-style image definitions.
  Live mode shows inline images away from the cursor; clicking moves into their
  untouched Markdown for editing. Reference-style images remain source in Live
  mode. Inline images inside tables use the table renderer.
- Keep alt text; show readable placeholders for unavailable, denied, oversized
  or undecodable images. Scale images within the pane. Limit Source Preview to
  32 images and 32 MiB of unique image data per render; limit Live image widgets
  to 16 in each decoration pass. Browser decoding uses its own image limits.
- Freeze the source document handle before rendering so tab switching cannot
  resolve an old render against the new tab. Save As, internal renames and
  workspace changes invalidate image context. Source Preview's Refresh rereads
  images even when Markdown has not changed. Changed image files are not yet
  tracked independently by the file watcher; use Refresh or reopen the note.
- Browser-only development has no native file access; local image resolution
  is a desktop feature. Image insertion buttons, clipboard/drop imports,
  resizing commands, remote images and SVG are separate follow-ups.
