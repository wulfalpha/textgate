# 0.1.7: links between notes

Scope: relative Markdown links and `[[note]]` / `[[note|label]]` links open
notes in tabs. Preview links activate with a click; editor links activate with
Ctrl/Cmd+click or Ctrl/Cmd+Enter, leaving ordinary editing intact. Reuse open
tabs and preserve unsaved buffers. Source text is never rewritten.
Editor activation covers inline Markdown links and wiki links; reference-style
Markdown links can be followed in Preview.

Resolve paths relative to the current saved note, with the workspace root as
the base for Untitled notes. Wiki links may omit `.md`; look in the current
folder first, then the workspace root. Do not search recursively or silently
choose between duplicate basenames. Missing notes report an error rather than
creating files. Support heading fragments where a matching heading exists.

Native resolution retains existing file permissions. A linked note must be
inside the chosen workspace (after resolving symlinks), or already granted by
a native file dialog/open request. A document link cannot grant arbitrary
filesystem access. Without a suitable grant, explain that Open Folder or Open
is needed. Absolute paths, network paths and non-note file types are refused.

External web/mail links continue to show their destination; opening them in a
browser and local images are separate work. Code, front matter and escaped
brackets must not turn into wiki links. Both renderers must sanitize link HTML.
