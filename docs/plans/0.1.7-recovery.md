# 0.1.7: recovery and restored tabs

First milestone: periodic private recovery checkpoints, not autosaving over
Markdown files. The published 0.1.6 tag and packages remain unchanged.

## Behavior

- Snapshot dirty buffers, their exact line endings/BOM, cursor positions, tab
  order and active tab. Remember clean named tabs too.
- After an interrupted session, restore unsaved buffers as dirty. Named buffers
  retain the Rust disk baseline from before the crash, so outside changes still
  trigger the existing save-conflict dialog.
- After a normal quit, reopen named files from disk. Quit Without Saving drops
  draft text, including Untitled buffers; it must not resurrect discarded work.
- New launch requests wait until restoration finishes, then open normally.
- Recovery files live in Textgate's application-local data directory. Rust
  supplies the paths and baselines from existing document handles; JavaScript
  cannot nominate arbitrary paths to reopen.
- Write one versioned session file atomically with private permissions. Keep
  the previous checkpoint if writing fails. Unreadable/corrupt data is retained
  and reported, rather than silently replaced.
- Checkpoint after a short typing pause and at least every few seconds during
  sustained typing. A persistent warning makes checkpoint failures visible.

## Bounds and limits

Checkpoints are limited to 512 tabs and 64 MiB of serialized data. Exceeding
either limit reports a persistent warning and retains the previous checkpoint.

This milestone restores text and a primary selection, not undo history or
scroll offsets. It does not implement on-disk autosave, file watching or note
links. Checkpoints are best-effort and cannot preserve edits made since the
last successful write. Recovery data is local plaintext, protected by the
current user's application-data permissions; it is not encryption.

## Verification

- Byte-exact BOM/mixed-ending recovery, multiple documents and active tab.
- Interrupted write leaves the previous checkpoint intact.
- Saved/closed/discarded buffers do not reappear as unsaved work.
- Recovered named buffers detect outside edits and deletion on Save.
- Clean tabs read the current disk version at restart.
- Corrupt/unknown-version/oversized checkpoints remain untouched with a warning.
- Startup restoration precedes queued native opens; checkpoint writes serialize
  with file operations and cannot revive tabs removed while a write was queued.
- A native test app uses a separate identifier so crash tests do not interfere
  with the installed app or its documents.

### M4 Mac mini verification, 2026-11-05

The isolated Textgate Recovery Test app reopened two CLI-opened files after a
forced termination. A clean file picked up outside edits; a deleted file's
cached text returned dirty without recreating the source file. A prepared dirty
checkpoint preserved BOM/CRLF text and its previous disk baseline, and a third
file supplied at launch opened after restoration (three tabs, active index 2).
This fixture check does not replace typing and quit-dialog tests through the UI.
Those checks remain pending: computer control first reported an Accessibility
permission error, then briefly connected, then reported `Transport closed`.
