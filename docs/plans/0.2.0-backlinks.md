# 0.2.0: workspace index and backlinks

Implemented on `feature/backlinks`; not released. Existing saving and crash
recovery stay unchanged. Backlink indexing never writes source files.

## Behavior

- Choose **Backlinks** in the sidebar or View menu to list links to the active
  saved note inside the open workspace. Counts distinguish source notes from
  occurrences (for example, **3 notes · 5 links**), and partial counts are
  explicitly marked as a minimum. Each result shows its workspace-relative path,
  line number and source-line context. Multiple occurrences are listed separately.
- Clicking a result opens or reuses the source tab and moves to that link. An
  open source keeps its unsaved text and undo history. If the source line changed
  since indexing, open it and ask for a refreshed result rather than jumping to
  a stale offset. A deleted source with a retained open buffer reuses that tab.
- Inline and reference-style Markdown links and wiki links are parsed with the
  same comrak options used for Preview. Labels and fragments do not change the
  target's identity. Code, front matter, images, embeds, raw HTML anchors,
  remote links and same-document anchors do not produce backlinks. Self-links
  are omitted.
- Current editor contents override disk contents for every open workspace note,
  including clean tabs and unsaved changes. Closing a tab returns that source
  to disk indexing; saving does not require a separate backlink operation.
- ID links require workspace-wide uniqueness. Explicit paths and note extensions
  use navigation's current-folder/root fallback rules. Symlink aliases of one
  canonical note count once. Hidden entries and linked directories are not
  traversed, and no files outside the chosen workspace are scanned.

## Index and refresh

The native, in-memory workspace index caches parsed source text and links,
scopes its inventory to the chosen workspace, and assigns each query a revision.
It is rebuildable and has no disk cache or migration. Existing ID navigation
continues its own on-demand uniqueness scan; future consumers can build on this
index without changing navigation behavior prematurely.

While Backlinks is visible, edits and tab/workspace changes trigger a debounced
query. A full inventory/content reconciliation runs about every five seconds
(after the preceding query completes), on window focus, and on Refresh. This
covers collapsed folders and missed watcher notifications without changing the
existing file-browser watcher into a recursive watcher. Scanning and parsing run
on a native blocking worker; only one frontend request is outstanding at a time.
No periodic backlink queries run while the panel or sidebar is hidden.

Sidebar selection uses `textgate.sidebar.v2`, falling back to the existing
`textgate.sidebar` preference on first use. Unknown values select Outline.
The older preference is still written as Files or Outline (Outline when
Backlinks is selected), so downgrading does not leave an older build with an
unrecognized sidebar choice. Storage failures retain only the session choice.

Results are accepted only if the workspace, active tab, tab paths and all editor
text snapshots still match. The native scan also checks that its workspace grant
is unchanged before returning. Old responses cannot repaint a new workspace or
newer editor contents. Unchanged periodic results preserve their row elements.

Limits: 100,000 filesystem entries; 4 MiB per source note; 64 MiB of source
contents per query; 5,000 parsed links per source; about 100,000 parsed links
across sources (the last accepted source may cross that threshold); 2,000 visible
results. Open editor sources take priority over closed files. Oversized open
buffers produce an explicit error rather than falling back to stale disk text.
Unreadable/invalid UTF-8 files and scan/parse limits show partial-result warnings.
An incomplete inventory cannot establish ID uniqueness, so its ID backlinks are
omitted. Partial results never claim that no links exist in the whole workspace.

This is a read-only snapshot index with reconciliation, not a transactional
snapshot of outside filesystem activity. Rename updates will still require the
separate complete-scan, preview and conflict checks in the rename plan.

## Validation

Automated tests cover Markdown/reference/wiki discovery; code, image and front
matter exclusions; URL decoding; duplicate IDs versus explicit paths; UTF-8 and
incomplete-inventory warnings; symlink boundaries and alias deduplication; open
buffer precedence; deleted open sources; external edits, renames and deletion;
workspace changes; UTF-16 cursor columns; stale-response rejection and scan
coalescing; safe rendering; existing-tab reuse; and sidebar/menu wiring.

Final local macOS verification (2026-11-07), including rename updates, passed:
169 JavaScript tests, 96 Rust tests (94 unit and two CLI tests), production frontend build, Clippy with warnings denied,
formatting, manifest version consistency and `git diff --check`. Existing
nonfatal debug-stripping and frontend chunk-size warnings remain. Version is
still 0.1.7; no release or tag has been created for this work.

The user verified the initial Backlinks tab on macOS. An isolated macOS smoke
test additionally verified **2 notes · 3 links**, distinct `journal/Notes.md`
and `projects/Notes.md` folder context, and navigation into the existing source
tab. Full manual platform coverage remains pending on Linux and Windows; the
following checklist also covers macOS edge cases beyond that smoke test:

1. Create two saved notes in one open folder. Link from A to B using an ID wiki
   link and a Markdown path. Open B and choose Backlinks: both occurrences in A
   should appear with line context.
2. Click each result and verify that A opens at the matching link. Keep an unsaved
   edit in A and repeat: its text and undo history must be retained.
3. Add/remove a link in an unsaved source, switch back to B and verify results
   update without saving. Undo the source edit and verify the link reappears.
4. Edit, add, rename and delete a closed source outside Textgate, including in a
   collapsed subfolder. Results should reconcile within one refresh interval,
   or immediately on Refresh/focus.
5. Test duplicate IDs, code/front matter, a symlink alias, an unsupported-encoding
   note, and switching workspaces while indexing. Warnings and results must stay
   accurate; the feature must not write any note contents.
