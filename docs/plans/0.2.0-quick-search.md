# 0.2.0: quick note search

Implemented on `feature/quick-note-search`; not released. Version stays 0.1.7.

## Behavior and acceptance criteria

- **File → Quick Note Search…** or **Ctrl/Cmd+P** opens a modal filename/ID
  switcher. Without a workspace, offer to choose a folder first; cancellation
  changes nothing. Search does not inspect note contents or write files.
- In Vim Normal mode, `/` opens the same switcher. Insert mode retains literal
  slash input. Use Edit → Find… (Ctrl/Cmd+F) for searching within the current note.
- Match case-insensitive substrings of workspace-relative filenames and IDs.
  Space-separated words must all match. Exact filename/stem/ID matches rank
  first, then prefixes, filename substrings and folder/multi-word matches;
  ties sort by relative path. Empty search lists notes in path order. This is
  filename search, not full-text or fuzzy search.
- Show relative paths so same-named notes in different folders are distinct.
  Arrow keys change selection; Enter opens it; clicking a result also opens it.
  Escape or Cancel closes without opening or creating anything and restores
  focus. Existing tabs are reused through the normal document opener, retaining
  unsaved text, selections and undo history.
- Use the shared native workspace inventory: Markdown/text extensions, hidden
  entry exclusions, scope checks, no traversal of linked directories, canonical
  alias deduplication and duplicate-ID information. Duplicate IDs appear as
  distinct explicit paths; search never guesses which duplicate an ID link means.
  IDs from in-workspace file aliases can match their canonical note. Other alias
  filenames are not separate search entries. Untitled and deleted notes are not
  filesystem results; existing open tabs remain available in the tab bar.
- Native scanning runs on a blocking worker, one frontend request at a time.
  Typing is debounced 150 ms. Reconcile the inventory on each query, on Refresh,
  and every five seconds while the dialog is open. Preserve the selected path
  across periodic refresh when it remains present. Nothing polls after closing.
- Reject stale query responses and verify the current native workspace before
  and after scanning. A changed query immediately clears selectable old results.
  Opening still uses the normal native path/scope checks, so moved, removed or
  inaccessible results cannot bypass file permissions or create a missing note.
- Limit queries to 256 characters, scan to 100,000 entries and results to 100
  matches. Truncation, unreadable directories and incomplete inventories show
  explicit partial-result warnings. No matches under an incomplete scan is
  described as no matches in the notes checked. No new persisted settings.

## Validation (2026-11-07)

Passed 174 JavaScript tests and 100 Rust tests (98 unit, two CLI), production
frontend build, Clippy with warnings denied, formatting, version consistency and
diff checks. Existing nonfatal local `rust-objcopy`/libLLVM and frontend chunk-size
warnings remain.

New tests cover filename/ID/folder/Unicode matching and ranking; duplicate IDs;
shared scope/alias rules; entry/result/query limits; external creation/rename/
deletion reconciliation; safe rendering; keyboard selection; cancellation;
stale-response suppression and no stale Enter target; error/partial/Refresh
states; menu shortcut and Windows fallback wiring. Existing opener tests cover
tab reuse, alias reuse and preservation of unsaved work.

An isolated macOS debug app passed Cmd+P; filename search with two folder-distinct
results; arrow/Enter selection; exact ID search; reopening a dirty existing source
without adding a duplicate tab or losing its draft; no-match display; and Escape
returning to the same source. Temporary fixture notes and the isolated app use a
separate application identifier/recovery session from the normal Textgate app.

The user confirmed the initial quick-search feature worked on macOS. An additional
isolated macOS smoke test confirmed that Vim Normal-mode `/` opens Quick Note
Search, Escape restores editor focus, Insert-mode `/` inserts a literal slash,
and Vim undo removes that insertion. A focused Vim test covers the Normal-mode
action, unchanged source and mode, and Insert-mode pass-through. The user tested
commit `8edd2dd` on Linux and confirmed Vim Normal-mode `/` and Ctrl+P both work
as expected. The user also confirmed Vim `/` and Ctrl+P search work on Windows
using the MSI artifact from the same commit. The additional Linux/Windows cases
below have not been individually confirmed.
Test filename and ID search, keyboard and mouse opening, cancellation, reuse of
an unsaved tab, and Refresh after creating/renaming/deleting a closed note.

Final code review found and fixed a periodic-refresh selection race: a keyboard
selection made during a background scan could revert to the selection from
before the scan. The regression test first reproduced the wrong note being
selected, then passed after preserving the currently highlighted path when the
response arrives. All 174 JavaScript tests, production frontend build, version
consistency and diff checks passed after this frontend-only fix. The 100 Rust
tests/Clippy/formatting results above apply to the unchanged native code. The
Linux/Windows shortcut reports apply to `8edd2dd`, before this review fix.
No unresolved blocking issue remains in this local code review.
