# 0.2.0 planning

Draft plan for the release after 0.1.7. This is not a release checklist or
authorization to bump versions or publish artifacts.

All five in-scope features are now merged through PRs #11–#13. Release
preparation and remaining verification are tracked in the
[0.2.0 release checklist](../release-checklist.md#v020-release-preparation).

## Goal

0.2.0 is the Zettelkasten release: the smallest set of features that lets a
workspace of linked notes be written, navigated and reorganized without
leaving Textgate. It builds on 0.1.7's file browser, tabs, note links and
file watching. A shared workspace index is new work for 0.2.0, not an existing
0.1.7 capability. Saving stays explicit, with 0.1.7's private crash recovery.

## In scope for 0.2.0

1. **New notes with ID names.** A New Note command creates a note in the
   workspace named with a timestamp ID prefix (`202611071530 Title.md`) and
   opens it in a tab. 0.1.7 does not match links by ID, so 0.2.0 adds it:
   `[[202611071530]]` and `[[202611071530 Any title]]` find the note with that
   ID anywhere in the workspace, and duplicate IDs are reported.

   Decided defaults (implemented on `feature/id-notes`): 12-digit local
   `YYYYMMDDHHMM` IDs, moving to the next free minute when one is taken; the
   name is `ID Title.md`, or `ID.md` when the title is left blank; notes are
   created in the workspace root with a `# Title` heading; File → New Note…
   (Ctrl/Cmd+Alt+N) and a file-browser button; without a workspace, offer to
   open one. Links may name IDs of 12–14 digits to accept other tools' IDs.
   ID links are resolved by workspace-wide uniqueness before filename lookup;
   a matching local filename cannot hide duplicate IDs. An explicit note
   extension (`.md`, `.markdown`, `.txt`) or path such as `./ID Title` selects
   normal file lookup instead. ID links require an open workspace; symlink
   aliases of the same canonical note count once, while distinct matching
   paths report an ambiguity. Labels and heading fragments keep their existing
   behavior; this rule changes target resolution only.
2. **Create a note from a missing link.** Following a link to a missing note
   offers to create it (with an ID name or the link's own name) instead of only
   reporting an error. Nothing is created without that confirmation. See
   [creation behavior and validation](0.2.0-missing-notes.md).
3. **Backlinks.** A sidebar panel lists the notes that link to the current
   note, with the linking line as context, updated from the new workspace index
   as files change. Clicking an entry opens that note at the link.
   Implementation and validation: [workspace index and backlinks](0.2.0-backlinks.md).
4. **Rename updates links.** Renaming a note in the file browser offers to
   update the Markdown and wiki links that point to it across the workspace,
   showing the actual changes first. **Rename and Update Links** applies the
   reviewed operation; **Rename Only** changes the filename/tab paths without
   rewriting contents; **Cancel** changes nothing. Stable ID links stay intact
   during title-only renames. Open buffers receive undoable edits and remain
   unsaved; closed files are rewritten only after confirmation and conflict
   checks. Stale plans stop for a new preview; partial failures report completed
   and pending work without silently rolling back or overwriting files. See
   [rename behavior and acceptance criteria](0.2.0-rename-links.md).
5. **Quick note search.** A keyboard-driven switcher finds notes in the
   workspace by file name and ID and opens them. Full-text search is not
   required for 0.2.0.
   Implementation and validation: [quick note search](0.2.0-quick-search.md).

## Workspace index prerequisite

Current ID lookup (`src/notes.rs`) recursively scans folders on demand. The
file browser lists folders as needed, and the existing watcher reports disk
changes; neither maintains a workspace-wide inventory of notes and links.

Before implementing backlinks, rename updates or quick search, add a shared,
in-memory workspace index with these acceptance requirements:

- Inventory supported note paths and IDs, retaining duplicate-ID information
  and scope checks. Preserve the existing rules for hidden entries and
  symlinks; aliases of one canonical note must not create duplicate results.
- Parse outgoing Markdown and wiki note links, with source positions and line
  context, using the same link syntax and target-resolution rules as navigation.
  Links inside code must not become backlinks or rename edits.
- Use open editor contents for open notes, including unsaved edits; use disk
  contents for closed notes. Update when buffers change, save, close, or move,
  and when files are created, changed, renamed or deleted outside Textgate.
- Build and refresh without blocking editing. Watcher notifications are
  invalidation hints: reconcile after missed events or watcher failures, and
  prevent an older scan from replacing newer buffer or workspace state.
- Track workspace identity, revision and scan completeness. Switching folders
  clears the old state. Unreadable files, scan limits and unsupported content
  must be visible as incomplete results, not a claim that no links exist.
- Backlinks and search may show clearly marked partial results while indexing;
  rename updates require a complete, fresh scan and the separate preflight
  checks in [the rename requirements](0.2.0-rename-links.md). An index alone
  does not authorize a disk write or replace conflict checks.

Tests must cover initial discovery, unsaved-buffer precedence, external file
changes, duplicate IDs, symlink scope, incomplete scans, and stale work finishing
after a buffer edit or workspace switch. Keep this index private and rebuildable;
it requires no persisted cache or migration for 0.2.0. Existing on-demand ID
scans can remain until indexed lookup preserves their uniqueness and failure
behavior. This prerequisite does not add full-text search to the release.

## Moved to 0.2.1

These are useful but not needed for the core write–link–navigate–rename loop:

- **Tags**: `#tag` parsing, a tag list and filtering notes by tag.
- **Graph view** of notes and links.
- **Full-text search** across the workspace (beyond quick note search).
- **Optional source-file autosave.** Conflict, deletion, recovery, Save As
  and outside-edit behavior must be defined first; it stays off by default.
- **Per-image remote loading.** Remote images stay blocked by default. A
  "Load image from example.com" action may allow one image for the current
  session only, with no document-wide permission or background preloading.
- **Image import and editing**: paste/drop images into notes, SVG support and
  image size/alignment controls.

## Before implementation

- Write acceptance tests for each in-scope item first.
- Rename must never rewrite a file without showing the change, and must keep
  untouched bytes, UTF-8/BOM and line endings, matching existing save behavior.
  Other encodings must be reported, not decoded lossily or silently converted.
- Define migration/compatibility behavior for any new persisted setting.
- Windows parity: Windows manual checks still trail macOS and Linux; record
  untested platforms explicitly rather than marking them passed.
