# Textgate v0.1.4

This release adds command-line and file-manager opening, preserves mixed line
endings by default, and makes line-ending normalization an explicit choice.

## Markdown remains authoritative

- Saving an unedited UTF-8 file preserves its bytes, including mixed LF/CRLF/CR
  line endings, a BOM, whitespace and final-newline presence.
- Edits retain existing line endings; new breaks use the file's predominant
  style. Undo/redo restore line-ending metadata as well as text.
- **Edit → Normalize line endings…** explicitly standardizes to LF, CRLF or CR.
  It is undoable and triggers unsaved-change protection even without text edits.
- Save snapshots include line-ending metadata so continued editing cannot change
  which version is marked as saved.

See the README for the preservation policy and the CR/LF adjacency edge case.

## Command-line and file-manager opening

- Open `textgate notes.md`, quoted or relative paths, and local `file://` URLs.
- Use `--` before a filename beginning with a dash. `--help` and `--version`
  work without opening a window.
- Open a missing path as an empty named document; create the file only on Save.
- Send a second invocation to the existing window using the caller's directory.
- Queue incoming opens during file operations and protect unsaved changes.
- Register `.md` and `.markdown` associations, including native Finder events.
- Reject multiple paths clearly in the single-document UI.

Atomic saves and external-change detection apply to native launches as well as
Open dialogs. Files created externally at a prepared-but-unsaved path require
confirmation before replacement.

## Downloads and installation

| Platform | Download |
| --- | --- |
| Linux x86-64 | `.AppImage`, `.deb` or `.rpm` |
| macOS Apple Silicon | `aarch64.dmg` |
| macOS Intel | `x64.dmg` |
| Windows x64 | `x64-setup.exe` or `x64_en-US.msi` |

On macOS, copy Textgate from the DMG to Applications. Mac packages are ad-hoc
signed, with signatures verified in the release workflow, but are not notarized.
If macOS blocks a trusted download, open **System Settings → Privacy & Security →
Open Anyway** and approve the launch prompt. This flow was verified on an M4 Mac
with the downloaded 0.1.4 app, without manual re-signing. A fresh M1 installation
and native Intel launch remain unverified; older 0.1.3 packages are unchanged.

Windows installers remain unsigned. If SmartScreen warns for a download you
trust, choose **More info → Run anyway**. For the Linux AppImage:

```sh
chmod +x Textgate_0.1.4_amd64.AppImage
./Textgate_0.1.4_amd64.AppImage
```

The `.app.tar.gz` files are not needed for normal Mac installation.

## Validation

- Hosted Checks passed on Linux, macOS and Windows; all four package jobs passed.
  Version/tag consistency and JavaScript/Rust tests run before release packaging.
- Local M4 validation passed 80 JavaScript and 21 Rust/CLI tests, formatting and
  Clippy. Mixed/BOM saves, normalization, undo/redo, file conflicts, deletion and
  recreation, Save As, queued opens, CLI first launch and path variants were tested.
- The freshly installed M4 app matches the downloaded release byte for byte and
  passes strict signature verification. The DMG checksum also verifies.
- Windows 11 MSI and Arch Linux AppImage smoke tests were user-verified, including
  stable fonts and normalization appearing in Edit. Detailed platform checks
  remain tracked in the release checklist.

For repeatable checks, download `Textgate_0.1.4_save-fixtures.zip` and follow
`START-HERE.txt`, or see the [package testing guide](../testing-0.1.4.md).

## Limits

The CLI does not add a PATH entry, accept stdin/`--wait` or multiple paths, or
open at a line/column. Linux single-instance forwarding uses session D-Bus.
There is still no autosave, crash recovery or file watching.
