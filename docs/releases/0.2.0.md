# Textgate v0.2.0: linked-note workspaces

Draft release notes. Source preparation is in progress; 0.2.0 packages have not
yet been verified or published. The latest published release remains 0.1.7.

0.2.0 adds ID-named notes, confirmed creation from missing links, backlinks,
reviewed rename link updates and quick note search. Saving stays explicit, with
private crash recovery for drafts.

## Create and link notes

- **File → New Note…** (Ctrl/Cmd+Alt+N) creates a workspace note with a local
  timestamp ID: `YYYYMMDDHHMM Title.md`, or `ID.md` with no title. Taken IDs
  advance to the next free minute. A title adds a Markdown heading.
- Wiki links such as `[[202611071530]]` or `[[202611071530 Any title]]` find a
  unique ID anywhere in the workspace. A title-only rename preserves that ID.
  Duplicate IDs are reported instead of choosing an arbitrary note. Explicit
  paths/extensions continue to use normal file lookup.
- Following a missing note link offers a creation dialog. Choose an ID filename
  or the link's own filename; Cancel creates nothing. Parent folders must already
  exist. Confirmed ID creation can update the clicked source link as an undoable,
  unsaved edit. Undo does not delete the newly created note.

## Backlinks

- Choose **Backlinks** in the sidebar or View menu to see notes linking to the
  active saved note. Counts distinguish source notes from link occurrences;
  results show workspace-relative paths and the linking line.
- Click a result to open its source at the link. Existing tabs retain their
  drafts and history. Current open buffers participate without being saved.
- The native workspace inventory reconciles outside changes while the panel is
  visible and on refresh/focus. Scan limits and unreadable notes are explicitly
  marked as partial results. Code, front matter, images and self-links do not
  produce backlinks.

## Rename with reviewed link updates

- Renaming a note offers a before/after preview and **Rename and Update Links**,
  **Rename Only**, or **Cancel**. Cancel changes nothing. Rename Only leaves
  source contents untouched and can break name-based links.
- Confirmed updates change parsed Markdown/wiki destinations while preserving
  labels, aliases, fragments and unrelated bytes. ID-based links stay unchanged.
  Existing note ID prefixes must be retained. Folder moves/link rewrites are
  outside this feature.
- Open-note updates are undoable and remain unsaved. Closed notes are written
  through conflict-checked atomic replacement. Undo affects one editor, not the
  filename or other files. Unsupported encodings/incomplete scans block bulk
  updates instead of silently converting or skipping unreviewed content.
- Changed sources, destination collisions and stale previews stop the operation.
  Completed changes are retained after a partial failure; pending writes never
  resume automatically. A durable progress record preserves recovery drafts and
  offers a fresh review of remaining work. No global rollback is implied.

## Quick note search

- **File → Quick Note Search…** (Ctrl/Cmd+P) finds workspace notes by filename or
  ID. Results include folder context; matching ignores case and accepts multiple
  words. Use arrows/Enter or click to open, and Escape to cancel.
- Existing tabs are reused without replacing unsaved text. Search reconciles
  outside changes, rejects stale responses and reports scan/result limits. It
  searches names and IDs, not note contents.
- In Vim Normal mode, `/` opens Quick Note Search. Insert-mode `/` remains text.
  Use **Edit → Find…** (Ctrl/Cmd+F) to search within the current note.
- A review fix keeps your current highlighted note when a background refresh
  finishes, including selection changes made while that scan was running.

## Verification and packages

Features were merged through PRs #11–#13. The final feature review passed 174
JavaScript tests and 100 Rust tests (98 unit and two CLI), frontend build,
formatting, Clippy and version checks. Hosted checks passed across Linux, macOS
and Windows. Release-version checks and package verification are tracked
separately in the [0.2.0 checklist](../release-checklist.md#v020-release-preparation).
The integrated 0.2.0 source also passed the same 174 JavaScript/100 Rust tests,
frontend build, Clippy, formatting and version/proposed-tag checks locally.
Hosted release-preparation checks and final package checks are still pending.

User feature testing covered note creation/recovery on macOS, Linux and Windows;
backlinks on all three; rename choices, link updates and editor undo/recovery;
rename collisions, closed-source stale-preview rejection and case-only rename
with working links/tab names on all three; and search shortcuts on all three.
The detailed records distinguish smoke tests from individually unconfirmed
cases. Manual interruption between individual closed-file writes was too fast
to exercise reliably; automated tests cover that interruption and durable
progress recovery. Remaining manual search/refresh edge cases stay documented.

Expected packages are Apple Silicon and Intel Mac DMGs/app archives, Windows
x64 MSI/NSIS installers, and Linux x86-64 AppImage/DEB/RPM packages. Downloaded
0.2.0 candidate installation/runtime results and checksums are pending. Earlier
feature artifacts still report 0.1.7 and are not final 0.2.0 packages.

Mac packages use ad-hoc signatures and are not notarized. Windows installers are
unsigned, and Windows spell checking remains broken. Intel Mac runtime and
DEB/RPM installation have not been manually verified for this release. Follow
the [README installation guidance](../../README.md) for packages from this repo.

## Still deferred

Tags, graph view, full-text search, optional source-file autosave and per-image
remote loading remain deferred to 0.2.1. Remote images stay blocked. Outgoing-link
browsing is outside the agreed 0.2.0 scope. No automatic updater is included.
